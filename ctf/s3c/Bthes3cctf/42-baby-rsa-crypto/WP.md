# 42 BabyRSA · Crypto

- 分类：Crypto ｜ 分值：214 ｜ 状态：平台已解
- 模数只有 256 bit（两个 128 bit 素数相乘），分解之后就是标准 RSA 解密。

## 题目

附件 `BabyRSA.zip` 里只有 `BabyRSA.py`：

```python
p = getPrime(128)
q = getPrime(128)
flag = b's3c{********}'
m = bytes_to_long(flag)
e = 65537
n = p * q
c = pow(m, e, n)
```

脚本末尾把 `c`、`n` 以注释形式给出，题面只留这两个数。

## 思路

- `p`、`q` 各 128 bit，`n` 只有 256 bit，属于「现代机器随手可分解」的规模，不需要任何特殊攻击。
- 拿到 `p`、`q` 后走最标准的流程：`phi = (p-1)(q-1)`，`d = e^{-1} mod phi`，`m = c^d mod n`。
- `e = 65537` 与 `phi` 互素（两个素因子都是大素数，不会撞上 65537），求逆一定存在。
- 明文只有十来个字节，`m < n` 是必然的，不存在低指数问题，纯粹考「n 太小」。

## 关键步骤

1. 打开 `BabyRSA.py`，把注释里的 `c`、`n` 抄下来：

   ```python
   c = 33946131301255476943212274474168449852967537654715614961823901479381558655242
   n = 3727589256575656195350032536697963149981061622443249159795599771759126456873
   ```

2. `n.bit_length()` 是 256，先确认规模：

   ```python
   >>> n.bit_length()
   256
   ```

3. 分解 `n`。这一步靠工具完成：把 `n` 交给现成的整数分解工具，256 bit 的规模很快就出结果。本机当时没有留下具体分解命令的记录，只留下分解结果：

   ```python
   p = 184184962971941265573609502233646626943
   q = 202382930529650105560007753996882823511
   ```

4. 回到交互环境，代回校验分解结果，再求私钥并解密：

   ```python
   >>> p*q == n
   True
   >>> phi = (p - 1) * (q - 1)
   >>> d = pow(e, -1, phi)
   >>> from Crypto.Util.number import long_to_bytes
   >>> long_to_bytes(pow(c, d, n))
   b's3c{welcome_to_cryptography}'
   ```

## 踩坑 / 备注

- 脚本里的 `p`、`q` 是直接写死的，分解动作本身没有留档（用到的分解方式未记录），能确认的只有 `p * q == n` 且两者均为 128 bit。
- 这类题别急着套 Coppersmith / 共模之类的套路，先看一眼 `n` 的位长——256 bit 的 `n` 本身就是最大的漏洞。
